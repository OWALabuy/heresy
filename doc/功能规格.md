# HERESY（异端）功能规格（Python 重构版）

## 1. 目标与范围
- **目标**：提供跨平台的 Xray-Core 管理工具，完成订阅管理、节点解析入库、配置生成、进程与系统代理控制及基础网络诊断，强调可维护性与安全性。
- **平台**：Windows 10+/11，常见 Linux 桌面环境（GNOME/KDE 等）。
- **不包含**：翻墙能力本身（由 Xray/Hysteria2 实现）、复杂策略路由编辑器、流量统计可视化。

## 2. 术语
- **订阅**：机场提供的 base64 文本，含多条节点链接。
- **节点**：具体代理服务入口，协议如 `vless`/`vmess`/`trojan`/`hy2`。
- **当前节点**：被选择用于生成配置并启动代理的节点。

## 3. 功能列表
### 3.1 订阅管理
- 添加订阅（名称、URL）
- 列出订阅
- 更新订阅（下载→解码→逐行解析→入库；覆盖原有节点）
- 删除订阅（级联删除其节点）
- 编辑订阅（修改名称、URL）
- 批量更新订阅（可选增强）

### 3.2 节点管理
- 列出节点（全部/按订阅）
- 选择当前节点（持久化 currentNodeId）
- 节点延迟测试（ICMP ping 或 TCP/HTTP 探活，可配置次数/超时）
- 导入单个节点链接（手动添加，选做）
- 导出节点为链接（选做）

### 3.3 配置生成
- 基于当前节点生成 Xray 配置 JSON（含 inbounds、outbounds、routing）
- 默认 inbounds：本地 `socks5:10808`、`http:10809`，可配置
- 路由规则默认直连 `geosite:cn`、`geoip:cn/private`，UDP 53 指向 `dns-out`
- 协议适配：`vless`/`vmess`/`trojan`/`hy2` 的出站片段生成
- 配置输出目录：`~/.heresy/xray_config.json`（Windows 用用户目录等效路径）

### 3.4 进程管理
- 检查 Xray 是否运行
- 启动 Xray（带配置路径，捕获日志/返回码）
- 停止 Xray
- 对 `hy2` 节点：按需启动/停止 Hysteria2，并与 Xray 生命周期关联
- 进程启动的安全性：使用子进程 API，避免命令注入

### 3.5 系统代理控制
- Windows：设置/清除系统代理（HTTP/HTTPS 指向 127.0.0.1:10809；可配置端口）
- Linux（GNOME 优先）：使用 `gsettings` 设置/清除代理（HTTP/HTTPS/SOCKS）
- 代理状态查询与回退策略（无桌面环境时提示手动设置）

### 3.6 日志与诊断
- 记录关键操作日志（订阅更新、配置生成、启动/停止进程、系统代理变更）
- 基础诊断命令：显示当前节点、配置路径、进程状态、最近错误

### 3.7 配置与数据
- 数据库存储：SQLite（沿用 `~/.heresy/heresy.db`），表：`subscribes`、`nodes`
- 应用配置：YAML/JSON（端口、默认路由、下载超时、命令路径等）
- 兼容既有数据结构（尽量无迁移，必要时提供迁移脚本）

## 4. 交互方式（CLI）
示例命令树（Typer / Click）：
```
heresy
  subscribe
    add        # 名称、URL
    list
    update     # [id|--all]
    edit       # id
    delete     # id
  node
    list       # [--subscribe id]
    select     # id
    ping       # id [--count 3 --timeout 1000]
  config
    generate   # 基于当前节点
    path       # 显示配置路径
  proxy
    start      # 启动 Xray（与 hy2 协调）
    stop
    status
  sys-proxy
    enable     # [--port 10809]
    disable
    status
  diag
    info       # 当前节点、进程、配置等
```

## 5. 非功能需求
- 跨平台：Windows / Linux
- 安全：避免命令注入、对输入做校验、最小权限原则
- 可维护性：模块化、类型校验（pydantic）、单元测试（pytest）
- 可观测性：结构化日志、可选文件日志
- 可分发：PyInstaller 打包单文件/单目录

## 6. 数据模型（概要）
- Subscribe：`id, name, url`
- Node：`id, subscribe_id, protocol, uuid, addr, port, info, type, encryption, security, extra_params`
- 额外：`meta` 表存 `current_node_id`，或单独配置文件保存

## 7. 兼容性与迁移
- 读取现有 SQLite 与目录 `~/.heresy/`
- 不改变现有表结构的前提下读取/写入；如需新增字段，提供迁移脚本

## 8. 开放点与后续增强
- 批量测速（并发 TCP/HTTP）
- 规则管理（订阅/自定义路由合并）
- REST API 与前端面板/TUI
- 托盘与开机自启

## 9. 风险与约束
- Linux 各桌面环境代理设置差异大：需做能力检测与回退
- 某些环境禁用 ICMP：延迟测试需支持 TCP/HTTPS 替代
- 外部二进制路径（xray/hysteria）需要用户提供或自动发现

---
本规格面向 Python 重构第一阶段（CLI 版）。实现中优先保证订阅更新、节点选择、配置生成、进程与系统代理控制的稳定与一致性。
