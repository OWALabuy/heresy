# 数据模型与存储（与现有 SQLite 兼容）

## 1. 目录与文件
- 数据库路径：`~/.heresy/heresy.db`（Windows 使用用户目录等效路径）
- 配置输出：`~/.heresy/xray_config.json`
- 应用配置（可选）：`~/.heresy/config.yaml`

## 2. 表结构（沿用现有）
### 2.1 subscribes
- id INTEGER PRIMARY KEY AUTOINCREMENT
- name TEXT NOT NULL
- url TEXT NOT NULL

### 2.2 nodes
- id INTEGER PRIMARY KEY AUTOINCREMENT
- subscribe_id INTEGER
- protocol TEXT NOT NULL
- uuid TEXT NOT NULL
- addr TEXT NOT NULL
- port INTEGER NOT NULL
- info TEXT
- type TEXT
- encryption TEXT
- security TEXT
- extra_params TEXT

外键：`subscribe_id` → `subscribes(id)`，ON DELETE CASCADE（逻辑保证）。

## 3. 业务实体（Python 数据模型建议）
使用 pydantic/SQLModel：
- Subscribe(id, name, url)
- Node(id, subscribe_id, protocol, uuid, addr, port, info, type, encryption, security, extra_params)

说明：
- `protocol` 取值：`vless|vmess|trojan|hy2`。
- `extra_params` 用于协议特有字段的 JSON（如 SNI、TLS、obfs 等），兼容旧结构下可为空。

## 4. 当前节点的持久化
两种方案：
1) 在数据库新增 `meta(key TEXT PRIMARY KEY, value TEXT)`，键为 `current_node_id`。
2) 写入 `~/.heresy/config.yaml`：
```yaml
current_node_id: 12
inbound:
  http_port: 10809
  socks_port: 10808
```
重构优先采用方案(2)，避免修改既有表；若将来需要集中配置，再补(1)。

## 5. 订阅更新写入策略
- 全量覆盖：更新订阅时，删除该订阅下旧节点，再批量插入新节点。
- 失败回滚：采用事务（BEGIN/COMMIT/ROLLBACK），解析失败不写入。
- 最小字段校验：`protocol/uuid/addr/port` 必填，异常行计数与记录。

## 6. 解析与存储映射
- vless：`type`(tcp/grpc/ws)、`encryption`、`security`(tls/reality)
- vmess：`type`、`security`(auto/aes-128-gcm/chacha20-poly1305)、`tls`
- trojan：`type`、`sni`
- hy2：`sni`、`obfs`、`obfs_password`、`insecure`
- 以上协议特性若无法落在标准列，写入 `extra_params` JSON。

## 7. 索引与性能
- 为 `nodes(subscribe_id)` 建索引
- 为 `nodes(protocol)` 可选建索引（列表筛选）

## 8. 迁移策略
- 第一阶段不修改表结构，仅读取/写入既有字段。
- 若引入 `meta` 表或索引：提供 `--migrate` 命令执行一次性迁移脚本。

## 9. 数据一致性
- 删除订阅 → 级联删除节点（应用层保证）
- 选择当前节点时，必须存在对应 `nodes.id`，否则清空选择
